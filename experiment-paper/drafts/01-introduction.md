# 1. Introduction

Equation-oriented process models are valuable because a common set of first-principles equations can represent process design, performance-rating, and operating studies. This flexibility is increasingly important for interconnected process systems and digital-twin applications, where model components must be assembled, reused, and reconfigured across purposes \citep{shacham1982equation,walmsley2024adaptive}. Yet the flexibility also creates a recurring practical problem: the equations and variables exposed by a model do not state which variables its author intended a client to specify, nor how that choice should change when the study intent changes.

Consider a pump in a geothermal-power flowsheet. In a performance-rating calculation, pump work may be specified together with efficiency. In a study based on a measured downstream condition, the modeller may instead need to specify outlet pressure and calculate the work required to achieve it. Similarly, a heat exchanger may be configured by a heat-transfer coefficient for one study and by an outlet enthalpy or temperature target for another. In a conventional algebraic modelling language (AML), both changes are expressed as low-level operations: fix a formerly free variable, unfix another variable, assign values and initial guesses, and then establish that the altered model remains suitable for solution. The relationship between the imposed physical target and the released quantity is usually implicit in scripts, comments, or the modeller's knowledge.

This is an interface problem, not merely a variable-counting problem. An AML can expose the variables and constraints that define a component while concealing the intended specification choices through which that component is used. The omission becomes more consequential as components are composed into flowsheets: a flowsheet author must infer each component's expected baseline specifications, account for connections and external conditions, and reconstruct a consistent specification after changing a study target. The same implicit knowledge is needed by graphical clients, automation tools, and AI coding agents. A diagnostic can report that a model is over- or under-specified, but that result does not identify the semantically appropriate specification to exchange, the reason for the exchange, or the initialization procedure associated with it.

We present `pyomo-replace`, a specification-management framework for equation-oriented process models in the Pyomo/IDAES ecosystem \citep{hart2011pyomo,miller2018next,lee2021idaes}. The framework makes specification intent an explicit, inspectable interface. A unit-model author registers **Canonical Variables**, the ordinary specifications for a block, and labels them with **Specification Categories** such as inlet, operation, design, or initial condition. A client can then activate a tracked **Replacement**: a non-canonical variable is fixed as the specification and its associated Canonical Variable is released as a **Guess Variable**. The resulting record captures both sides of the exchange and its category, rather than treating the altered fixed status of variables as the only representation of intent.

The framework is deliberately a layer over, rather than a replacement for, equation-oriented modelling and its diagnostics. It preserves the baseline *count* of specifications by pairing the activation of one non-canonical specification with the release of one Canonical Variable. This invariant makes a configured flowsheet easier to inspect and return to a baseline configuration, but it is not a proof of independence, structural nonsingularity, feasibility, or numerical convergence. Choosing a physically and structurally suitable Replacement remains a modelling task supported by existing structural and numerical diagnostics.

This paper makes four scoped contributions:

1. It formulates model specification as an explicit interface for reusable equation-oriented components, separating intended specification choices from the equations that describe the component.
2. It presents a Pyomo/IDAES framework with a flowsheet-owned API, category-labelled Canonical Variables, and provenance-preserving Replacements that maintain the baseline specification count by construction.
3. It shows how the interface supports model composition, study reconfiguration, and staged initialization from Canonical Variable guesses across alternative specifications.
4. It evaluates the complete workflow in constrained AI-agent configuration tasks on chemical-process flowsheets. In the recorded geothermal and heat-integration cases, the Replacement workflow required less session time and fewer failed model executions than direct fixing. This evidence is limited to the tested agent, prompts, templates, and runs; it does not establish general AI performance, human usability, or a universal numerical-robustness benefit.

The remainder of the paper first establishes the equation-oriented modelling context and identifies the missing specification-management abstraction. It then defines the framework and its invariants, demonstrates its use on chemical-process flowsheets, and reports the bounded agent-assisted evaluation. The central claim is therefore not that a different set of fixed variables changes the underlying mathematics. Rather, explicit specification interfaces make those choices composable, interpretable, and more operable by software clients.
